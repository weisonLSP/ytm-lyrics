## 1. 背景与问题陈述

YouTube Music 没有高质量的桌面歌词方案。Lyricify 是当下最成熟的歌词软件，但其主力产品 Lyricify 4 仅支持 Spotify 且主体闭源，无扩展接口；Lyricify 3 的多播放器路线已被作者亲手 EOL。直接向 Lyricify 请求 YTM 支持不可行。

现有油猴脚本方案（YTM 挂载 QQ 音乐歌词）受双重上游漂移影响（YTM 前端改版、QQ 音乐接口变更），已多次失效。根因是脚本内聚了过多职责：监听、搜索、解析、渲染全在浏览器沙箱内，任何一层上游变动都会击穿整体。

Lyricify 作者已将歌词处理层开源（Lyricify.Lyrics.Helper，Apache 2.0，.NET Standard），包含六源搜索、QRC/KRC 解密、多格式解析。该供应链可直接复用。

## 2. 产品目标

为 YouTube Music 提供 Lyricify 形态的桌面歌词体验：

- 独立桌面歌词窗口 + 主窗口歌词面板
- 逐行滚动起步，逐字卡拉 OK 为储备能力
- 多源歌词自动搜索，本地缓存，手动校正兜底
- 架构上为未来的 Android 端预留通道（Core 与 UI 完全分离）

一句话：**探针薄、引擎厚、展示独立。**

## 4. 用户场景与验收

**S1 正常播放**：YTM 播放任意歌曲 → 3 秒内桌面歌词出现并跟随滚动，暂停即停，拖动进度条歌词跳转到对应行。
验收：连续播放 10 首不同语种歌曲，8 首以上自动命中正确歌词，滚动无肉眼可见卡顿。

**S2 自动搜索失败**：搜索无结果或结果错误 → 主窗口提示，用户手动输入关键词搜索，从候选列表选择后绑定，该曲目下次播放直接使用绑定结果。
验收：手动绑定后重播该曲，命中绑定歌词且不再发起自动搜索。

**S3 无歌词歌曲**：纯音乐或多源均无结果 → 显示"暂无歌词"，不反复重试。
验收：同一首歌 24 小时内只自动搜索一次（负缓存）。

**S4 探针中断**：浏览器关闭或脚本未运行 → 桌面端 10 秒内感知，歌词窗口隐藏或显示待机，浏览器恢复后自动重连。
验收：杀掉浏览器进程再恢复，无需重启桌面端即可继续工作。

**S5 YTM 改版**（不可主动验收，架构验收）：探针模块独立发布，修复面限于探针文件，桌面端零改动。

## 5. 功能需求详述

### F1 油猴探针（浏览器侧，~100 行 JS）

职责压缩到极限：读 `audio` 元素，报状态，别的什么都不做。

- 数据源：`HTMLAudioElement.currentTime` / `duration` / `paused`，`play` / `pause` / `seeked` / `ended` 事件
- 元数据：优先读 YTM 页面内部结构化数据（`ytInitialData` 等）；读不到则降级为 `document.title` + 频道名原始值，清洗交由桌面端（探针不做清洗，保持薄）
- 通信：WebSocket 客户端连本地 `ws://127.0.0.1:<port>`，自动重连（指数退避，上限 30s）
- 上报策略：事件触发（切歌/暂停/恢复/seek）+ 周期心跳（见 §6.4 协议）
- **设计红线**：不依赖任何 YTM 的 CSS 类名或 DOM 层级。`audio` 元素与事件是 HTML5 标准，是唯一信任锚点

### F2 播放状态服务（桌面端）

- WebSocket 服务监听本地端口（默认 17865，可配置）
- 维护"当前播放状态机"：曲目标识、播放中/暂停、最新 position 与时间戳
- 位置外推：两次上报之间用本地时钟插值推进 position，收到新快照时校正漂移（|漂移| > 0.8s 触发歌词跳行）
- 探针丢失检测：心跳超时 10s → 状态置为离线

### F3 标题清洗器（独立纯函数模块）

- 输入：原始标题、原始艺人（频道名）、时长
- 输出：清洗后歌名、艺人候选列表
- 规则表外置（JSON 配置，热加载）：剥括号对（`()` `【】` `[]`）、剥常见后缀（Official MV / Lyric Video / 4K / HD / Live / Cover…）、剥装饰符号与 emoji、分隔符拆分（` - ` `／` 等）推测歌名与艺人
- 纯函数、无副作用、单测覆盖；规则改动不动引擎

### F4 多源搜索引擎

- 源优先级（默认，可配置）：QQ音乐 → 网易云 → 酷狗 → 汽水 → Apple Music → Musixmatch
- 策略：首选源匹配分达标即返回；不达标顺延；全部不达标则返回"低置信结果"并标记（UI 提示用户确认）
- 匹配打分：歌名 + 艺人 + 时长三维比对（复用 Helper 的 CompareHelper），时长容差 ±3s
- 并发与节流：同源请求串行，异源可并行；单源最小请求间隔 500ms
- 全部失败 → 负缓存（记录"无歌词"，24h 内不再搜）

### F5 解析与时间轴

- 依托 Lyrics Helper 解析 QRC/YRC/KRC/LRC/TTML → 统一内部模型（行列表，每行含起始时间、可选逐字时间轴、可选翻译行）
- 同步降级保留：逐字缺失时以逐行渲染，模型层无感
- 当前行定位：二分查找 + position 外推，60fps 驱动下开销可忽略

### F6 本地缓存

- 存储：单文件嵌入式数据库（LiteDB 或 SQLite，实现期二选一，选型标准：单文件、零本地依赖、支持按索引查询）
- 缓存键：`sha1(cleanTitle + cleanArtist + durationBucket)`，durationBucket 按 ±3s 归并
- 缓存内容：原始歌词文本（不二次解析的源格式）、来源、命中时间、用户绑定标记、offset 微调值
- 用户手动绑定（F9）优先级高于一切自动结果，永久有效

### F7 桌面歌词窗口

- WPF 窗口：无边框、真透明背景、置顶、可拖动换位、尺寸可调
- 鼠标点击穿透：设置开关，开启后窗口不拦截任何鼠标事件
- 渲染：当前行高亮放大，上下行渐隐；逐行为 P0，逐字卡拉 OK（QRC 逐字时间轴驱动的填充动画）为 P1
- 歌词为空时窗口自动隐藏或显示极简状态（可配置）
- 与主窗口面板的关系：两种形态并存，**默认显示主窗口面板**，用户可在设置中切换默认形态

### F8 主窗口

- 当前播放信息（封面可选，v1 可用 YTM 返回的缩略图 URL）
- 完整歌词面板：整首歌词滚动视图，点击行可查看时间戳
- 手动搜索入口、当前命中来源显示、缓存管理（清除单条/全部）
- 设置页：端口、源优先级排序、穿透开关、清洗规则文件路径

### F12 补充：翻译行

- QRC 等格式自带翻译行时**默认显示**，设置中可关闭

### F9 手动校正

- 主窗口输入歌名/艺人 → 按当前源优先级逐源搜索 → 候选列表（显示来源、时长、歌词预览前几行）→ 选定后写入缓存并标记 userBound
- 解除绑定：删除 userBound 标记，回落到自动搜索

## 6. 技术设计

### 6.1 选型决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 桌面端语言/框架 | C# / .NET 8 + WPF | 零成本复用 Lyrics Helper（.NET Standard）；透明置顶穿透窗口原生支持；Lyricify 4 已验证该路线 |
| 探针载体 | 油猴脚本 | YTM 的一切形态（网页/PWA/Chrome 壳 app）均是 Chrome 页面，油猴全场景可达；维护者已有油猴经验 |
| 探针↔桌面通信 | WebSocket over loopback | 浏览器沙箱内最自然的双向通道；桌面端实现简单；天然支持未来多探针 |
| 歌词供应链 | 引用 Lyricify.Lyrics.Helper | Apache 2.0；六源搜索、QRC/KRC 解密、多格式解析均为实战代码；优先 NuGet，无包则 git submodule 固化版本 |
| 缓存存储 | LiteDB | 纯 .NET 嵌入式，单文件，零本地依赖，API 简洁；自用规模下 SQLite 的生态优势用不上 |
| 跨平台预留 | Core 零 UI 依赖 + IPlaybackProvider | 未来 Android 端（.NET MAUI）只写 UI 与探针实现，引擎原样继承 |

### 6.2 解决方案结构

```
ytm-lyrics/
├─ probe/
│  └─ ytm-lyrics-probe.user.js       # F1，唯一运行在浏览器内的代码
├─ src/
│  ├─ YTM.Lyrics.Core/               # 纯类库，禁止引用任何 UI 框架
│  │  ├─ Playback/                   # 状态机、位置外推、IPlaybackProvider
│  │  ├─ Playback/Providers/         # WebSocketProbeProvider (F2)
│  │  ├─ Cleaning/                   # 标题清洗器 (F3)
│  │  ├─ Engine/                     # 多源搜索、打分、fallback (F4)
│  │  ├─ Timeline/                   # 统一歌词模型、当前行定位 (F5)
│  │  ├─ Cache/                      # 缓存读写、负缓存、用户绑定 (F6)
│  │  └─ External/                   # Lyrics Helper 引用与防腐层
│  ├─ YTM.Lyrics.Desktop/            # WPF，仅渲染与窗口 (F7/F8/F9)
│  └─ YTM.Lyrics.Core.Tests/         # 清洗器、打分、时间轴单测
└─ docs/
```

防腐层说明：Core 内部模型不直接暴露 Helper 的类型，External 层做一次性转换。Helper 升级或更换库时影响面限于该层。

### 6.3 数据流

```
YTM 页面
  → [audio 元素] 探针采集
  → WebSocket → F2 状态机（快照 + 本地外推）
  → F3 清洗（新曲目时一次）
  → F6 缓存查询 ─命中→ F5 时间轴
       ↘未命中→ F4 多源搜索 → 解析 → 写缓存 → F5
  → 时间轴 + position → F7/F8 渲染
```

### 6.4 WebSocket 协议（v1）

探针 → 桌面端，JSON 文本帧：

```json
{
  "type": "state",
  "seq": 1024,
  "track": { "title": "原始标题", "artist": "原始频道名", "duration": 234.5 },
  "position": 67.2,
  "playing": true,
  "sentAt": 1786531200000
}
```

- `state`：事件触发立即发（切歌时 track 变化、playing 翻转、seek），稳态时 2s 心跳（track 摘要 + position）
- `seq` 单调递增，桌面端丢弃乱序帧
- 桌面端 → 探针（v1 仅一帧）：`{ "type": "hello", "version": "1" }` 建连确认
- 协议字段只增不改，版本差异靠 hello 协商

### 6.5 关键非功能指标

| 指标 | 目标 |
|---|---|
| 切歌到歌词显示 | ≤ 3s（缓存命中 ≤ 300ms） |
| 滚动帧率 | 稳定 60fps，当前行定位开销 < 1ms |
| 桌面端常驻内存 | ≤ 200MB |
| 探针失效爆炸半径 | 仅 probe/ 目录内文件 |
| Core 层 UI 依赖 | 0（CI 上可加引用检查防回归） |

## 8. 风险登记

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | YTM 元数据脏，自动匹配错词 | 体验差 | 清洗器 + 三维打分 + 低置信提示 + 手动绑定兜底 |
| R2 | YTM 前端改版击穿探针 | 功能中断 | 探针只依赖 HTML5 audio 标准；结构化数据读取失败时降级到原始标题 |
| R3 | QQ 音乐变更 QRC 加密/接口 | 首选源失效 | Helper 上游跟进；多源自动降级；已缓存歌词不受影响 |
| R4 | 歌词源风控限流 | 搜索失败 | 请求节流、本地缓存、负缓存防重试风暴 |
| R5 | Helper 停止维护或协议变更 | 供应链风险 | Apache 2.0 允许 fork；submodule 固化已知可用版本；防腐层隔离 |
| R6 | iOS 平台封锁 | 未来移动端受限 | 移动端目标平台锁定 Android；iOS 不投入任何调研成本 |

## 9. 未来路线（仅记录，不承诺排期）

- Android 端：.NET MAUI + MediaSession 探针（`IPlaybackProvider` 第二实现），复用 Core 全部能力
- SMTC 探针：桌面端无脚本运行模式，需先实测 Chrome SMTC 进度精度
- 播放控制：探针反向注入（桌面端 → WS → 探针调用 audio 元素方法），协议已预留方向

## 10. 已确认决策（2026-08-12 冻结）

1. **命名**：`YTM.Lyrics`
2. **逐字渲染**：P1，v1 后补，不阻塞 M3 验收
3. **翻译行显示**：QRC 自带翻译时默认显示，可配置关闭
4. **默认形态**：主窗口面板为默认；桌面歌词横条并存，设置中可切换默认
5. **缓存选型**：LiteDB
6. **文档策略**：TDD 与 UI 规格文档均为开工前置交付物，作为执行 agent 的防漂移锚与评审基准
7. **协作模式**：k3 任架构师（设计/派单/评审），deepseek-v4-flash 任执行与压缩，k3 只读压缩摘要
